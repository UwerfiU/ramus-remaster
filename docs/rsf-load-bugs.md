# T1.4: Баги открытия .rsf в оригинале — результаты расследования

Дата: 2026-11-17. Расследовано оркестратором (субагент не успел, задача закрыта напрямую).

## Проблема (а): FileVersionException «File plugin not registered: Attribute.Doc.Way»

**Воспроизведение:** открытие `dest/doc/ru/Пример модели.rsf` (и других старых образцов)
падает с исключением при старте.

**Причина:**
- В `data/application_metadata.xml` внутри .rsf хранится список плагинов, которыми
  создавался файл (26–29 штук для старых образцов).
- `FileIEngineImpl.checkFileVersion()` (core/.../FileIEngineImpl.java, ~строка 355)
  требует, чтобы **каждый** плагин из списка был зарегистрирован в текущем приложении,
  и бросает `FileVersionException` на первом отсутствующем.
- `Attribute.Doc.Way` — плагин очень старых версий Ramus (образцы от 2009 г.,
  ApplicationVersion 1.0/1.2). В текущем коде его нет (grep по всем модулям пуст).
- Механизм толерантности **уже существует**: `FileIEngineImpl.open(file, ignoreFileVersion)`
  пропускает проверку целиком, но вызывающий код — `MemoryDatabase.createEngines()`
  (data-framework-common) — передаёт результат `isIrnoreUnregisteredPlugins()`,
  который **захардкожен как `return false`** (строка ~207).

**Реализованный фикс (T3.6, 2026-11-18):**
- `FileIEngineImpl.checkFileVersion()` и `checkProjectVersion()`: отсутствующие плагины
  больше не бросают `FileVersionException` — собирается полный список недостающих,
  выводится предупреждение в stderr (консоль/лог приложения), открытие продолжается.
- Данные отсутствующих плагинов при этом игнорируются, а при сохранении файла
  теряются безвозвратно (об этом предупреждение и сообщает).
- Проверка минимальной версии (`FileMinimumVersionException`) оставлена действующей —
  это защита от файлов будущих версий.
- Проверено: `Пример модели.rsf` и реальный файл пользователя 2009 г.
  (ApplicationVersion «1.0 beta4») теперь открываются.

## Проблема (б): H2 duplicate key в RAMUS_ATTRIBUTES при открытии «Enterprise activity.rsf»

**Воспроизведение:** первый запуск приложения с этим файлом падал:
`Unique index or primary key violation ... PRIMARY_KEY ... ON PUBLIC.RAMUS_ATTRIBUTES(ATTRIBUTE_ID)`.

**Что проверено (и исключено):**
- В `data/attributes.xml` образца **нет дубликатов** ATTRIBUTE_ID (67 строк, id 1–67 уникальны).
- Схема `database.sql` не содержит INSERT — таблица не предзаполнена.
- `persistents.xml` в обоих образцах идентичен и не пересекается с RAMUS_ATTRIBUTES.

**Настоящая причина (по стеку из лога запуска):**
```
at com.ramussoft.common.journal.Journal.redo(Journal.java:192)
at com.ramussoft.local.Runner.recoverySession(Runner.java:743)
at com.ramussoft.local.Runner.recoveryFiles(Runner.java:237)
at com.ramussoft.local.Runner.start(Runner.java:271)
```
Это **не импорт файла**, а восстановление сессии (механизм «восстановить несохранённую
работу»): при старте `Runner.start()` → `recoveryFiles()` сканирует
`%APPDATA%/Ramussoft/Ramus/sessions/`, для каждой найденной сессии открывает исходный
файл и **переигрывает журнал команд** (`Journal.redo` → `CreateAttributeCommand`).
Если приложение было убито без чистого завершения (taskkill /F, краш), сессия остаётся
на диске; при следующем старте реплей журнала создаёт атрибуты, которые уже присутствуют
в загруженной таблице RAMUS_ATTRIBUTES → нарушение первичного ключа.

Вывод: **данные образца и код импорта не виноваты** — виновато устаревшее состояние
сессий на машине + отсутствие устойчивости механизма восстановления к битым журналам.
На чистой машине (без stale-сессий) «Enterprise activity.rsf» открывается нормально
(аналогично «Model example.rsf», открывшемуся в той же среде).

**Рекомендуемый фикс:**
1. В `recoverySession`/`recoveryFiles`: любая ошибка восстановления конкретной сессии →
   аккуратно удалить эту сессию и показать пользователю сообщение
   («Не удалось восстановить сессию для X — она удалена»), а не сыпать стек-трейсом.
2. Обеспечить чистое завершение: при нормальном закрытии окна журнал/сессия должны
   очищаться (проверить, что dispose() главного окна вызывает close() движка).
3. Риск для совместимости: нулевой — меняется только поведение аварийного восстановления.

## Побочные наблюдения

- `WARNING: Type not found: Season.PlanField` — в старых образцах есть атрибуты типа
  «Season» (старый planning-модуль, удалён из кода). После фикса (а) такие атрибуты
  будут открываться без редактора; допустимо.
- До фикса (а) `Model example.rsf` был единственным образцом, открывавшимся без
  модификаций; после фикса (а) все три образца (`Model example.rsf`,
  `Пример модели.rsf`, `Enterprise activity.rsf`) открываются.
